# 装甲列车实现与测试

2026-11-18，按 [装甲列车规则 V6](ArmoredTrainRules.md) 接入 AI 列车。防空部件保持闲置。

## 测试关卡

主菜单进入欧洲战场，选择“击毁列车”。关卡默认解锁，对应 `assets/resources/missions/mission_destroy_train.json`，菜单关卡 ID 为 14。

- 参考欧洲第一关“村庄”的 8×6 尺寸及 36 格可用边界，重新设计地形和部署。一条 14 格闭环铁路环绕中央村落，容纳 11 节列车并保留 3 格空轨。
- 11 节前后对称编组：反坦克炮车、榴弹炮车、火炮/防空组合车、指挥车、煤水车、机车、煤水车、指挥车、火炮/防空组合车、榴弹炮车、反坦克炮车。
- 另有 2 队德军步兵、2 辆三号 N 型坦克；玩家使用谢尔曼。
- 玩家从西南公路进入，公路穿过村庄通向东侧，在西南、东侧两次跨越铁路。村内 3 处建筑为步兵提供据点，两辆三号 N 型部署在环内，所有普通单位初始均不占铁轨。外围林地与泥地提供道路外的接近路线。
- 目标是击毁整列列车。摧毁中央机车即可胜利，支援敌军与其余车厢不增加通关条件。

运行 `npm run train:mission` 可重建该关卡。它不配置随机增援事件。

## 关卡配置

铁路仍通过格子的 `rl` 六向端口配置。新增 `trainRoutes` 记录有序格子，`trains` 记录稳定编组及车厢 ID；不要在普通 `enemies`/`allies` 列表放置单独列车模块。

```json
{
  "trainRoutes": [{
    "id": "main", "loop": false,
    "cells": [{ "col": 0, "row": 3 }, { "col": 1, "row": 3 }],
    "entryDir": 3, "exitDir": 0
  }],
  "trains": [{
    "id": "train1", "routeId": "main", "sideId": "enemy", "entryTurn": 2,
    "carriages": [
      { "id": "train1_gun", "kind": "train_howitzer" },
      { "id": "train1_engine", "kind": "train_locomotive" },
      { "id": "train1_tender", "kind": "train_tender" }
    ]
  }],
  "objective": { "type": "destroy_train", "trainId": "train1" }
}
```

以上是字段片段；路线必须覆盖实际地图上的连续铁路。开放路线首尾的入口/出口方向必须通向图外。闭环使用 `loop: true`，省略入口/出口方向，且轨道长度至少为总车长加每列 2 格。不支持相反方向共用铁轨。任务加载、编辑器保存和导出均校验连接、容量、车厢身份及初始重叠。

`carriages` 从车头到车尾排列，包含至少一台机车。未指定 `entryTurn` 时直接部署，`headIndex` 表示最前车厢的路线索引，默认 `车长−1`。`entryTurn` 是回合末入场事件：触发后立即从路线入口外按 1/2 格速度逐格前进，后续回合继续进入，不在本次入场事件中攻击。

指定车厢任务使用 `{"type":"destroy_train_carriage","trainId":"train1","carriageId":"train1_gun"}`。图外车厢仍保留身份与状态；它们不进入场上目标或视野列表，未入场或已出图也不视为击毁。

## 运行时

`core/ArmoredTrain.ts` 管理编组和 `move → ambush → attack → done` 状态。移动开始锁定额度；每个步骤先更新前车占位，批量动画结束后结算伏击。所有机车被毁立即取消后续移动，煤水车途中被毁保留本次额度。全部移动结束后按编组配置顺序逐节攻击；每节一次，炮塔转不到位时只转向。

`BattleScene` 在普通车辆行动后、步兵前执行列车阶段，友方与敌方分别在所属 AI 阶段行动。它复用战场炮塔瞄准、掷骰、伏击、攻击结果与坦克残骸 SAT 推动。列车推残骸不减速，允许残骸离开地图；同格步兵保持原位并锁定移动。

`Combat` 使用列车击穿后的起火/击毁规则，并复用坦克 HE 与过穿；不生成乘员或瘫痪。视野区分车厢内部共享与指挥车对外无线电，全部机车被毁后切断对外共享。任务按原始机车名单或指定车厢 ID 判定，存档保存所有图内外车厢、行动队列、已走步数、锁定额度及逃脱失败状态。

列车不阻挡观察和射击视线，适用于未毁车厢、仍连挂的已毁车体及分离残骸。车体占格、同格步兵移动限制与残骸推动仍按编组状态处理；建筑、林地、烟雾等继续按原有规则遮挡。

绘制读取 BP44 manifest，车体与武器独立旋转，组合车防空武器保留独立朝向但不射击。击毁时掀飞武器，车体暂用无武器的正常贴图压暗，后续可替换为专用去炮塔击毁图。尚未完成 Cocos 现场操作验收。

车厢击毁后隐藏单位名称及“已毁”文字，仍连挂或已经分离的残骸均适用；未毁车厢保留名称。

转弯显示使用前后轮组在有序轨道上的采样位置计算车身中心和朝向，动画起止与静止姿态一致；弯道车厢不再直接朝向下一条格边。战场将每节车厢贴图中前后两端的固定车钩全部裁掉，用一根直连杆连接前车尾部与后车头部的车体安装点；连杆随两车姿态转动，不再形成“固定车钩＋中段补线”的 Z 字连接。分离后移除，双方均可见时才绘制，首尾外端不生成连接件。裁切使用独立 SpriteFrame；原始 PNG、车体比例、武器安装点和战斗占格不改变。`bodyBounds` 由正式车体轮廓生成，车体与独立炮塔仍保持原尺寸。

按用户补充，弯道车体在轮组姿态基础上进一步向内侧偏移，额外内收最多为相邻格心间距的 8%；进出弯平滑过渡，直轨不偏移，车体显示位置不绑定格子中心。武器、连接杆与名称使用相同显示位置。

连续炮车没有目标时，以独立的一次性回调推进攻击队列。Cocos 会对仍在执行的相同回调去重，因此不能在回调内部再次 `scheduleOnce(next)`；此处使用独立包装回调，避免列车结束后回合停住。

本次列车专项包含连续无目标车厢的 Cocos 调度去重复现、转弯姿态连续性、首尾车钩裁切和随动连接杆。正式资源合成对照位于 `source_art/trains/bp44-turning-20261118/bend-review.png`，不是 Cocos 实机截图。

此前扩展回归有 5 项既有失败：斜向射击的高差预期、随机关卡数量预期，以及诺曼底关卡的地图尺寸、登陆坐标和增援标记预期；使用列车改动前的相关核心文件也可复现，未在本次列车功能中改动这些规则或关卡。
