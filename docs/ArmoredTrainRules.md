# 装甲列车规则 V3

更新日期：2026-11-07。状态：用户已确定下列主体规则；本文记录设计，尚未实现列车战斗逻辑。

本文包含 2026-11-07 用户对 V2 的补充，替代此前冲突的描述。V1 中玩家控制、行动/装填额度、地形移动消耗、移动射击惩罚、瘫痪、维修、主动解编及原损伤表均不再适用；V2 的防空对地攻击和机车击毁后仍整体占格的描述也不再适用。未在本文确定的数值和边界行为不沿用旧版默认值。

## 1. 单位与编组

- 列车只作为敌方或友方 AI 单位出场，玩家不能直接控制。
- 使用已制作的 BP 44 风格模块；机车、煤水车和其他车厢均每节占一格。
- 整列按固定车厢顺序沿铁路移动；每节车厢具有独立身份、属性、坐标、起火和击毁状态。
- 机车未被击毁时维持整体编组；机车被击毁时自动分离为独立车厢，不需要脱钩动画或分离特效。原列车和车厢 ID 仍保留用于任务、存档和计数，保留这些身份不表示继续作为整体行动。
- 被攻击时，每节车厢单独视为一个单位，分别选择目标、计算距离、命中、装甲和受损结果。命中一节不把伤害传递给其他车厢。
- 列车没有乘员。不生成车长、炮手、装填手和驾驶员，不进行乘员伤亡、舱盖或岗位检定，也没有乘员属性加成。
- 车体和可旋转武器保持分件。榴弹炮塔、防空炮座和反坦克炮塔独立旋转；组合车两个部件保持独立朝向。

## 2. 行动时机与顺序

列车不投掷行动骰子。双方 AI 的列车行动均安排在对应的坦克行动之后、步兵行动之前：

`坦克行动 → 列车行动 → 步兵行动`

每列每回合行动一次，内部顺序固定为：

1. 确定本回合移动距离，先执行整列移动，所有车厢的移动动画同时开始、同时推进、同时结束。
2. 移动结束后，按配置的车厢排列顺序依次执行攻击阶段。
3. 每节未被击毁且具有常规对地攻击能力的车厢，寻找目标、旋转武器，并在能够瞄准时射击。防空武器不参加这一阶段。

一列的所有移动完成后才开始其车厢攻击，不边走边让各车厢射击。移动时不能播放“第一节走完，再让第二节走”的逐车动画；车厢沿轨道先后排列不等于逐节执行移动。机车尚未击毁时，已毁车厢也与其他车厢同步移动，但不执行攻击。

分离后的未毁车厢保留原本坦克后、步兵前的攻击时机；可按原车序稳定处理，但不能继续把它们当成有动力的整体。

## 3. 移动与动力

| 编组状态 | 每回合沿铁路前进距离 |
| --- | --- |
| 机车未被击毁，没有未击毁的煤水车 | 1 格 |
| 机车未被击毁，有至少一节未击毁的煤水车 | 2 格 |
| 机车已被击毁 | 0 格 |

- 煤水车可选；没有煤水车的列车仍可运行。增加多节煤水车不会把上述速度累加到 3 格或更多。
- 煤水车起火但尚未击毁时仍算存在；被击毁后继续随车移动，但不再提供加速。此项已由用户另行确认。
- 铁路上的田野、道路、泥地一律按相同速度通过，不检查基础地形移动成本。弯道也不增加移动消耗。
- 铁路仍是原格子的覆盖层；本条是列车的专用移动规则，不改变其他单位的地形规则。
- 只沿关卡预设路线中的相互连通铁路前进，不倒车，不因目标位置、障碍或岔道而自主改变路线。
- 各车厢在同一路线上按原车序保持间距并同步前进，不能离轨或跳过中间格；2 格移动须经过并处理两个相邻步骤。
- 每一步先确定全列新位置，再同步更新所有车厢。每节使用同一个动画进度，按各自所在轨道段插值；过弯不改变车厢顺序，也不把炮塔朝向强制改为车体朝向。
- 机车被击毁后自动分离，全体车厢停止前进。未毁车厢保留原位置且仍可攻击；已毁车厢（含机车）转为普通可推动残骸，见第 9 节。
- 普通车厢被击毁不会主动脱离、停止动力或留在原格。没有主动脱钩、独立拖曳或现场维修动作；机车击毁触发的自动分离是单独规则。

预设路线、事件驶入和驶出地图见第 3.1 节。不额外引入 V1 的转角/速度限制。

### 3.1 关卡路线与进出地图

- 关卡必须配置列车的有序前进路线，明确途经铁路格、入口和需要驶出时的出口。每列绑定指定路线，保存当前路线进度，不能只给出生朝向后依靠 AI 寻路。
- 道岔只执行预设路线中指定的下一格，不随机选出口，也不为了追击敌人驶入其他岔道。
- 路线中的相邻地图格须相邻且铁路端口互通；编辑器应校验完整路线、入口铁路格与出口连接。
- 列车可以初始就在地图中，也可以作为回合结束事件，在指定铁路格沿配置路线驶入地图。事件须引用完整编组、所属阵营、路线和入口，不能按普通单格坦克增援随机选择其他格子。
- 事件入场需要表现为整列从入口沿轨道驶入；尚在地图外的车厢不参与地图内占格、视野、攻击或防空，不能把全列同时堆在入口格，也不能逐节串行播放入场动画。
- 列车可以继续沿预设铁路出口驶出地图，不在地图边缘自动倒车。仍在地图内的车厢同步前进，越过出口的车厢退出地图内占格、视野、攻击和防空；不能车头出图就让整列瞬间消失。
- 分离后的车厢没有动力，不再继续按原路线出图。机车若在尚未完整入图时被击毁，未入图车厢如何参与任务另列待定。
- 入场与出图都保留稳定车厢 ID。未出现、在场、已出图、已击毁是不同状态；驶出地图不等于击毁。

事件驶入本身推进多少格、未完整入场的编组怎样初始化及无出口路线的终点行为，仍需补齐；不能因为入场事件发生于回合结束就额外赠送一次常规攻击。

## 4. 碰撞、残骸与同格步兵

### 坦克

- 列车移动进入有存活坦克的格子时，直接击毁该坦克，不投掷命中、穿甲或伤害骰。
- 用户未限定阵营，规则按敌我坦克均适用记录；不能因友方坦克占轨道而自动减速或停下。
- 列车移动时会推开坦克残骸，不减速。刚被列车撞毁的坦克残骸也按此规则处理，不能留在铁轨格阻止本次移动。
- 每个移动步骤都检查进入格，移动 2 格不能跳过第一格的坦克或残骸。
- 双格坦克的任一占据格受到列车撞击时，应按整辆坦克处理，不能只摧毁一半；其残骸整体移位方式列为待定边界。

### 步兵

- 步兵允许与列车处于同一格，不会因列车驶入而被碾压或强制移走。
- 与列车同格的步兵不能移动到其他格，直到列车离开该格。
- 该步兵留在地图原格，不随列车搭乘移动。
- 是否解除移动限制以整列本步更新后的占格为准。前一节离开、后一节立即进入同一格时，步兵仍被限制，不能在车厢交替时获得移动机会。
- 机车尚未击毁时，已毁车厢仍属于整体列车占格，同格步兵仍受限制。机车击毁并分离后，已毁车厢改为普通残骸，按普通残骸格规则处理，不继续施加“与列车同格”的移动锁定；同格若仍有未毁车厢则继续受限。
- 本规则只明确限制步兵移动；不自动附加压制、攻击失效或步兵伤亡。

### 列车车体

- 整体列车状态下，所有车厢均阻挡视野和坦克进入，无论是否已被击毁。共享视野不取消车体或其他地形的射线遮挡。
- 机车尚未击毁时，列车车厢残骸是随编组移动的车厢状态，不是可被当作坦克残骸推走的独立物件。
- 机车击毁并自动分离后，未毁车厢仍阻挡视野和坦克移动；已毁车厢转为普通残骸，不再阻挡视野和坦克通行，坦克可以进入并推动它。普通残骸与车厢状态必须区分。

## 5. 攻击流程与次数

**每节具备常规对地攻击能力的车厢每回合合计最多攻击一次。**防空武器不执行常规对地攻击，只在空袭事件中反制，见第 5.1 节。因此火炮/防空组合车在普通攻击阶段使用主炮，不能改用防空炮射击地面目标，也不会因防空炮多获得一次对地攻击。

每节车厢使用与反坦克炮相似的确定性攻击流程：

1. 寻找符合阵营、视野、武器目标类型、距离和射线要求的目标。
2. 选择本回合用于攻击的武器，按该车厢/武器配置的炮塔转向速度朝目标转动。
3. 当前回合能够转到目标方向，则旋转完成后立即射击；原本已对准则直接射击。
4. 当前回合不能转到位，则只完成本次允许的旋转，本回合不射击。剩余转角不能在同一回合用另一次车厢攻击补足。
5. 没有合法目标则不攻击；本节没有用掉的攻击次数不能转给其他车厢。

配置多个部件不增加车厢的对地攻击预算。组合车的主炮与防空炮不再作为同一阶段的二选一武器；两者在不同流程中发挥作用。

炮塔转速使用现有坦克相同的规则尺度与方向系统，但实际数值由车厢/武器配置，不能统一写死为牵引反坦克炮的转速。旋转炮塔只带动相应部件；另一门武器与车体朝向保持独立。

没有行动骰，也不使用 V1 的“装填一次或射击一次”动作消耗；正常情况下每回合都有一次攻击机会。移动后仍正常进入攻击流程，不附加 V1 自行提出的移动射击 +2 惩罚。

### 5.1 防空武器：只反制敌方空袭事件

- 防空武器不寻找地面目标，不单独加入常规攻击队列，只在回合结束事件或回合随机事件实际触发空袭类攻击时作为反制。
- 参考车长开舱反击斯图卡的事件顺序：空袭生效前寻找可反制的防空武器 → 结算对空射击 → 若飞机被击落则取消本次后续轰炸，否则继续原空袭结算。
- 必须先判断空袭来源的战斗阵营。只反制敌对来袭，不攻击己方或盟军的空袭；不能因为事件名称包含“斯图卡”就忽略其实际所属阵营。
- 反制依赖防空武器所在车厢尚未被击毁、仍在地图内。车厢被毁后不得防空；机车击毁后尚存的防空车厢不因停止移动而失去其防空用途。
- 列车没有乘员，防空不能要求车长存活或舱盖打开；指挥车是否存在也不作为防空武器本身能否反制的条件。
- 空袭因天气等原因没有真正发起攻击、仅播放飞过动画时，不自动当作一次需反制的空袭。
- 常规主炮攻击与事件防空属于不同触发流程，不把防空塞入车厢顺序攻击中，也不因主炮已开火就认定防空动作已消耗。

现有实现 `TurnEndEventApply.ts:simulateStukaReport` 在车长可反击时掷 2d6，合计 ≥6 则击落并跳过后续轰炸。该数值仅作为已核对的参考；列车防空的射程、命中门槛、多门防空与车长反制的先后顺序、每次事件反制次数尚未确认，不能默认每门各套一次判定后无限叠加。

事件数据须能够明确空袭来源阵营，并区分空袭效果与地雷/炮击等其他事件；回合随机事件和固定回合事件共用这套防空结算，不能只接入其中一种。

## 6. 逐车配置属性

每种车厢分别配置装甲与武器，不从整列或机车复制同一套数值。

| 范围 | 必要配置 |
| --- | --- |
| 车厢身份 | 唯一 ID、所属编组、排列顺序、模块类型、阵营 |
| 车体防护 | 命中体型值、正面/前侧/后侧/后方装甲，及适用的炮盾参数 |
| 常规武器 | 武器类型、可攻击目标、穿甲值、高爆威力、有效射程、炮塔转向速度 |
| 防空部件 | 安装位 ID、独立朝向、事件反制用途及待确认的防空参数，不注册对地攻击动作 |
| 多武器 | 各安装位的属性与朝向；每节最多一次常规攻击，防空另在事件流程触发 |
| 基础观察 | 基础视野 3 |
| 编组职能 | 是否机车、煤水车、指挥车 |

以上列出需要配置的属性；具体装甲、穿甲、高爆、射程和转速数值尚未确认。V1 的测试数值表不作为已批准配置。列车没有乘员，不能因缺少坦克乘员岗位字段而被判定为不能开火。

## 7. 视野共享与无线电

- 每节未被击毁车厢的基础视野为 3；车厢之间共享视野，整列内部使用各车厢有效视野的合并结果发现目标。
- 整体编组状态下，同列内部视野共享与对外无线电是两个机制。没有指挥车或指挥车被击毁后，整列失去无线电功能，但同列车厢之间仍共享视野。机车击毁并自动分离后的共享规则另列待定。
- 至少一节指挥车未被击毁时，列车具备无线电功能；起火但尚未击毁的指挥车仍可提供无线电。对外收发条件沿用当前模式的无线电规则，不产生乘员要求。
- 被击毁车厢不再主动提供观察。整体编组状态下仍阻挡视线；自动分离后转为不挡视线的普通残骸。未毁车厢无论是否仍连挂均阻挡视线。
- 共享视野用于目标发现；攻击仍须通过开火位置到目标的射线检查，不能透过阻挡视线的车厢或地形开火。
- 被攻击时各车厢的可见性分别判定，看到一节不等于能够攻击整列所有车厢。

现有普通 AI 的“必须有自身直接视野才能开火”限制，不能直接用来否定本规则的同列共享；列车内部共享的攻击可见性须单独接入。来自列车以外的无线电情报是否可直接用于射击，仍按游戏原有规则处理。

## 8. 起火与击毁

未被击毁车厢在遭到击穿后只产生两种受损状态：起火、击毁。不生成瘫痪、炮塔受损、无线电损坏或乘员伤亡。

| 受击前状态 | 击穿后的结算 |
| --- | --- |
| 未起火 | 掷 1d6：1～4 起火；5～6 击毁 |
| 已起火 | 直接击毁，不再掷车厢损伤骰 |
| 已击毁 | 保留已击毁状态，不能重新计为一次击杀 |

- 起火本身不等于击毁，不满足击毁任务条件，也不自动停止列车。
- 机车、煤水车、指挥车均按是否被击毁判断其功能，不因单独起火附加未规定的失效。
- 起火车厢尚未被击毁，因此具有攻击能力的起火车厢继续按每回合一次的流程行动。
- 列车损伤不能直接套用普通坦克可能产生瘫痪的 HE 或方向损伤结果；所有攻击入口都须尊重列车专用状态集合。HE 如何判定车厢受到有效伤害列为待确认细节，不能在实现时自行替换上述明确的击穿后伤害表。
- 不自动增加灭火/维修、持续火势伤害或跨车连环爆炸规则。

## 9. 击毁后的表现与行为

- 车厢击毁时，相应炮塔被掀飞；多炮塔/炮座车须处理各独立武器部件的击毁表现。
- 击毁后隐藏可用武器，车体切换到被击毁状态，不再提供攻击或观察。
- 机车未被击毁时，已毁车厢仍保持原车序，跟随机车同步移动，继续阻挡视线和坦克移动；不能提前按普通残骸清理或释放其占格。
- 机车被击毁时自动分离，不额外播放车厢拉开、脱钩或散开的动画/特效。所有车厢保留当时位置，全列不再移动。
- 分离生效时，把所有已经击毁的车厢（含机车）转为真正普通残骸：不再阻挡视野与坦克通行，可被坦克推动；后续对未毁车厢的攻击若将其击毁，也直接转为这种普通残骸。
- 分离时未毁车厢停在原地，仍可在列车攻击时段行动；它们仍是阻挡视野和坦克移动的独立单位。
- “正常/起火/已毁”是每节车厢的受损状态，“整体编组/自动分离”是编组生命周期。残骸行为必须同时取决于二者，不能把同一张击毁贴图当作完整判定条件。
- 掀飞部件是击毁表现，不额外生成阻塞铁路的静态残骸实体。

现有 BP 44 资源已将车体和正常武器分件，但完整击毁图仍含武器残骸；后续需补充/调整去炮塔的击毁车体与掀飞表现，避免飞走一套炮塔后车体上又出现同一套武器。当前美术绘制单元未实现该效果。

## 10. 任务条件

支持两种列车相关任务条件：

1. **击毁指定车厢**：通过稳定的车厢 ID 指定目标，通常为机车；目标状态变为已击毁时达成。起火和停止移动均不等于击毁。
2. **击毁所有车厢**：指定列车编组中所有车厢都被击毁才达成，包括机车、煤水车、指挥车和所有武器车。

任务使用初始/事件声明的稳定车厢名单和已击毁状态，不依赖当前是否仍组成整体、车厢对象被删除或单位列表为空。机车击毁只满足对应的指定车厢目标，不自动完成整列全灭；分离后其余车厢仍属于原任务追踪名单。残骸转换、推动和再次播放动画不能重复计数。

尚未入场和已经驶出地图的车厢均不算击毁；不能因当前地图没有目标车厢而提前判定全灭。任务需要指定目标逃出地图后的结果，见待定边界。

## 11. 尚未确认的边界细节

以下不影响上述已确定规则的记录，后续实现前补齐，不从 V1 继承答案：

- 编组长度、是否限制单机车，以及初始车序/朝向的配置格式。
- 无出口的预设路线终点如何处理，以及遇到另一列车如何处理；道岔只按预设路线前进、禁止倒车和可沿铁路出图已经确定。
- 多列车同回合的稳定执行顺序；现有支援炮等其他 AI 单位在总队列中的位置保持其规则，另行确定与列车的衔接。
- 常规攻击目标优先级；可参考现有反坦克炮的“非步兵优先 → 转角较小 → 距离较近”，但不把它写成用户已确认的新限制。防空炮不再参与对地武器选择。
- 防空射程和判定门槛、多门防空/车长反制的先后与次数；两个事件阶段都需要支持，敌我判定不能省略。
- 事件入场一次推进多少格、是否跨数回合完整入图，以及入场过程如何处理机车尚在图外或提前被毁。
- 指定目标/部分目标驶出地图后，是任务失败、累计到另一目标还是其他关卡行为；不把出图计为击毁。
- 自动分离后，各独立未毁车厢是否继续内部共享视野、如何获得原指挥车的对外无线电支持。
- 每种车厢的实际装甲、武器数值和命中体型；是否配置单独的炮手视野。
- 坦克残骸被推向哪个相邻位置；没有合法空位、双格残骸及地图边界时如何摆放。无论具体方案如何，不能因此令列车减速。
- 列车遇到反坦克炮、卡车等非坦克占格物时的处理。
- HE 对车厢的有效伤害判定，以及现有过穿等机制对列车专用损伤表的适用方式。
- 步兵攻击同格车厢的具体流程，以及额外强制位移能否解除同格移动限制。
- 列车移动如何触发伏击；若两步移动之间机车被击毁，后续步骤应停止，普通车厢被击毁则继续保留编组移动。

## 12. 后续实现验收要点

- 只有友军/敌军 AI 可以激活列车，没有玩家操作入口和行动骰托盘。
- 坦克后、步兵前行动，所有车厢同一进度同步移动，整列结束移动后再严格按车序攻击；不得逐节串行动画。
- 无煤水车走 1 格，有未击毁煤水车走 2 格，各种基底地形和弯道速度一致。
- 煤水车被击毁后速度降为 1；机车未毁时普通车厢被击毁不阻止移动。机车击毁触发无额外特效的自动分离，全体停止移动。
- 各列只按预设路线前进，经过岔道不改道，不倒车；事件可从指定铁路入口驶入，列车可沿路线出图。
- 移动两步分别处理途中坦克、残骸和步兵，不能跳过中间格。
- 坦克直接被撞毁，残骸被推开且不减速；步兵留原格且在有效车厢占格时无法移出，自动分离后仅剩普通残骸的格子不再施加列车移动锁定。
- 每节常规攻击车厢最多一次对地攻击；转到位当回合立即射击，转不到位只转向。防空武器绝不加入常规攻击队列。
- 两种事件阶段的敌方空袭均可触发防空，己方/盟方空袭不触发；成功击落后不得继续轰炸。
- 不同车厢转速、装甲和武器属性独立配置，没有乘员前置条件。
- 整体编组状态下同列共享基础 3 格视野；无未击毁指挥车失去对外无线电但保留内部共享。分离后的共享方案待明确后补充对应验收。
- 击穿后 1～4 起火、5～6 击毁；已起火再被击穿直接击毁，其他坦克损伤不混入。
- 机车未毁时炮塔掀飞后的车体仍连挂、同步移动、挡视野和坦克移动；未毁车厢始终挡视野。
- 自动分离后，已毁车厢转为不挡视野、可被坦克进入和推动的普通残骸；未毁车厢原地继续攻击。分离后再击毁车厢也须转成普通残骸。
- 指定车厢和整列全灭任务按稳定 ID/编组名单与击毁状态计算。
- 存读档保留原车序/任务 ID、路线/入口/出口及进度、入场/出图/分离状态、各车受损、残骸身份和显示偏移、武器朝向与回合行动进度；已毁和已分离车厢仍须恢复。
