# 装甲列车美术设计

日期：2026-11-06；规则关联更新：2026-11-07。阶段：第一版六种模块美术已完成，AI 列车主体规则已确定，玩法尚待接入。

## 用户已确定

- 每节车厢占 1 个六角格。
- 炮塔数量与位置可以参考德国 BP 44 或 BP 42 设计。
- 已选择 BP 44 风格，并确认先制作本文所列六种模块。
- 铁路作为田野、道路、泥地上的覆盖层；列车仅作为双方 AI 单位，具体规则见 [装甲列车规则 V3](ArmoredTrainRules.md)。

## 已采用的美术结构

采用 BP 44 风格的模块化车厢，保留 BP 42/44 的火炮、防空组合车特征。以下为游戏美术方案，不预先规定列车编组长度、车厢独立受损、武器射界或战斗数值。

机车和煤水车也按单格模块制作。车体与武器采用统一正俯视、透明背景和基准朝向；车体、可转动炮塔/炮座分件，转轴分别标定。

| 模块 | 武器部件数量 | 本方案的位置与外观 |
| --- | --- | --- |
| 装甲蒸汽机车 | 0 | 装甲锅炉外罩、驾驶室、烟囱；前后车钩独立标记 |
| 装甲煤水车 | 0 | 煤仓、水箱、检修盖，保持与机车一致的连接高度 |
| 指挥/步兵车 | 0 个独立炮塔 | 封闭装甲车厢、观察舱盖、侧面机枪射孔；射孔作为车体细节 |
| 榴弹炮车 | 1 个榴弹炮塔 | 车体纵向一端的多面炮塔，另一端留装甲舱室 |
| 火炮/防空组合车 | 1 个榴弹炮塔 + 1 个四联装防空炮座 | 分置车体前后，保持两个武器轮廓及转轴清楚可辨 |
| 反坦克炮车 | 1 个四号坦克式炮塔 | 低矮装甲车体中央附近，保留长炮管与炮塔尾箱特征 |

先制作以上 6 种车体。若后续需要完整展开历史风格编组，再增加坦克运输平板车；运输的坦克与车厢分件。

## 第一批资源清单

- 6 张正常车体：带武器车体不包含可转动武器。
- 6 张完整击毁残骸：每种车体一张，对应原车体长度和锚点；武器残骸可合并进整节残骸。
- 3 张正常武器部件：榴弹炮塔、四号坦克式炮塔、四联装防空炮座。榴弹炮塔可在两种车厢上复用。
- 合计 15 张核心 PNG；共享车钩/连接件、图标、转向架按后续表现需求补充。
- 每节标记前后车钩、轮组/转向架中心、车体基准点；武器标记转轴、炮口，机车标记烟囱。

## 单格与连接验收

- 每节车体按一个格子制作，纵向压缩细节以适配游戏尺度，统一车宽与轮距。
- 车体两端给连接件留出空间，沿铁路连接时保持车钩位置一致。
- 检查直轨、连续弯轨和道岔上的连接；每节朝向与其所在轨道的表现相协调。
- 独立武器的图片中心与转轴分开标记；图中看起来能转动不代表已确定可用射界。
- 检查游戏缩放下能区分机车、榴弹炮车、防空组合车与反坦克炮车。
- 维持现有单位的简化细节与清晰轮廓；不把武器数量、机枪射孔数量直接换算成规则攻击次数。

## V1 交付与使用

正式资源目录：`assets/resources/textures/units/trains/bp44/`。包括 6 张正常车体、6 张整节残骸、3 张独立武器，共 15 张 512×512 RGBA PNG，配套不裁边的 Cocos SpriteFrame 元数据。

`bp44_art_manifest.json` 是本批美术的统一注册入口：记录模块类型、资源路径、车体中心、前后车钩、轮组中心、烟囱、独立武器安装点、武器初始朝向和实际炮口位置。当前 schemaVersion 为 2，每个武器安装位带有唯一的 `slotId` 和 `rotationMode: "independent"`。组合车有两条武器安装记录，后端四联装炮座初始朝向 180°。

像素坐标使用左上角原点、X 向右、Y 向下；源图车头朝上。画布密度为逻辑像素的 2 倍：逻辑六角半径 128 对应源图半径 256；车钩间距为 `sqrt(3) × 128 × 2` 源图像素，对应一个格心间距。若游戏六角半径为 R，整张源图的显示尺寸为 `2R × 2R`，坐标相对画布中心按 `2R / 512` 缩放；Cocos 本地 Y 坐标需要翻转。

正常合成预览从同一车体和独立武器确定性合成；整节击毁图按正常车的车钩轴线和两端长度作统一比例注册，不单独紧裁后铺满。损伤保留原有灰蓝涂装和较大面积正常亮度，使用大破口、翻折装甲、局部焦黑及个别断炮表现。

源图、几何定位图、全部 15 份内置 imagegen 提示词、注册参数、校验报告和三类预览位于 `source_art/trains/bp44-v1-20261106/`。预览包括正常/击毁总表、R=48 的实际显示尺寸及半尺寸检查、直轨和弯轨的静态组合示意。弯轨示意中的连接杆用于美术检查，不代表已有列车运动实现。

当前交付是可导入 Cocos 的独立美术资源包。AI 列车主体规则已记录在 [装甲列车规则 V3](ArmoredTrainRules.md)，具体车厢属性和部分边界行为待补齐；尚未向只支持现有 UnitKind 的坦克 CSV 注册列车，也未实现列车移动、射界、伤害或编组玩法。后续列车绘制应读取本批 manifest 的多武器记录，而不是把组合车当作只有一个炮塔的普通坦克。组合车主炮每回合最多一次常规对地攻击；防空炮只在两种回合事件的敌方空袭中反制，不参与常规攻击。

V3 规定所有车厢使用同一进度同步移动，不能逐节播放移动。车厢击毁时炮塔掀飞；机车未毁时已毁车体仍随列车移动并保留遮挡、占格。机车击毁后逻辑上自动分离，不额外播放分离特效；已毁车体转为普通可推动残骸，不再阻挡视野和坦克通行，未毁车体停在原地继续攻击。现有完整击毁图含武器残骸，后续须补充去炮塔的击毁车体及掀飞表现；不能直接把整张击毁图显示作为最终效果。

```powershell
npm run train:prepare
npm run train:audit
npm run typecheck
npm run train:validate
```

修改生成母图后先运行 `node tools/prepareArmoredTrainArt.cjs register` 更新注册参数。正常重建不会重新请求图像生成服务。审计检查 15 张 PNG 的透明度、画布、唯一 UUID、Cocos 导入尺寸与 UV、车钩、分层合成、实际炮口、残骸注册和损伤差异；已完成合成图及小尺寸目视检查，尚未进行 Cocos 中的列车现场验收。

## 独立武器旋转

正常车厢的三种武器均为独立透明 PNG；车厢图片只保留底座/安装环。榴弹炮车使用 `main_gun`，组合车使用 `main_gun` 与 `anti_aircraft` 两个互不关联的旋转槽，反坦克炮车使用 `anti_tank`。炮管与相应炮塔/炮座作为一个武器部件绕自身转轴旋转。

`assets/scripts/view/ArmoredTrainVisual.ts` 提供可复用的 Cocos 节点绘制单元，`assets/scripts/core/ArmoredTrainArt.ts` 提供共用的支点与炮口变换。车厢节点与每个武器节点同属一个不旋转的根节点；安装位置跟随车厢，武器角度独立保存。转动车厢不会覆盖武器当前瞄准方向，转动组合车一端的武器不会带动另一端。角度使用战场坐标中的 Cocos 逆时针角，0° 朝上；这不同于清单初始角度所用的 PNG 顺时针约定。

```typescript
const art = await loadArmoredTrainArt();
const visual = new ArmoredTrainVisual(parent, art, 'artillery_flak', hexRadius);
visual.setWeaponAngle('main_gun', 90);
visual.setWeaponAngle('anti_aircraft', -45);
visual.setPose({ x, y, angleDegrees: 60 }); // 两个武器保留各自角度，安装点随车体移动。
const muzzlePoints = visual.getWeaponMuzzles('anti_aircraft');
```

击毁状态沿用坦克方式，显示整节残骸并隐藏活动武器节点。绘制单元已提供，战斗场景中的火车单位注册和射界等规则仍按后续需求接入。

`previews/bp44-independent-rotation.png` 展示分层与不同角度；`previews/bp44-independent-rotation.html` 是可离线打开的交互预览，可分别拖动车厢、主炮、防空炮和反坦克炮的角度。预览与 Cocos 节点共用支点/炮口计算。专项测试覆盖独立节点、双武器互不影响、车体转向保留瞄准、六朝向及不同缩放、实际炮口旋转、残骸切换、贴图共享和交互控制。
