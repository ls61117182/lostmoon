# 坦克俯视图制作与接入规范

本文档描述六角格战斗地图使用的坦克俯视 PNG 主流程。现行流程以独立车身、独立炮塔、完整俯视图、击毁图和 `data/tank_visuals.csv` 中的源像素几何为准；不再使用统一放大整组图片或从完整图按硬编码区域拆分炮塔的旧流程。

## 1. 目标与原则

- 在实际地图显示尺寸下，车型轮廓、炮塔和主炮方向必须清晰可辨。
- 参考图或现有已确认图片是几何权威。生成和后处理不得随意改变车体长宽比、首尾结构、履带范围、炮塔环、炮塔转轴和炮口位置。
- AI 只用于确有必要的重绘。裁切、缩放、配色、描边、图层组合、坐标换算和元数据同步应采用确定性处理。
- 删除小比例下无法辨认的微小零件，不得为填充画面凭空增加结构。
- 用户选定某个生成版本后，后续修改必须从该版本或它的备份继续，不得重新生成近似版本替代。

## 2. 资源组成与命名

资源目录：`assets/resources/textures/units/`。

可旋转炮塔的分层坦克使用：

| 文件 | 用途 |
| --- | --- |
| `{kind}_top_hull.png` | 无炮塔车身，运行时随车体旋转 |
| `{kind}_top_turret.png` | 独立炮塔和炮管，运行时可独立旋转 |
| `{kind}_top.png` | 按正式转轴组合的完整俯视图，用于预览和回退 |
| `{kind}_top_destroyed.png` | 以最终车身图为基础制作的击毁状态 |

固定战斗室、固定火炮或不需要炮塔独立旋转的单位可以只提供 `{kind}_top.png` 和 `{kind}_top_destroyed.png`。此时完整俯视图承担车身权威图的角色。

所有 PNG 必须使用透明背景并带 Alpha 通道。资源路径、车型列表和运行时几何统一配置在 `data/tank_visuals.csv`，不在 `BattleScene.ts` 中逐车硬编码加载分支。

## 3. 尺寸与比例规则

### 3.1 车身

- 车身尺寸按非透明内容的 Alpha 包围盒测量，不按整个透明画布测量。
- 测量时把 `alpha >= 32` 视为车身内容；内容包围盒的最长边必须小于或等于 **150 px**。
- 缩放时必须保持车身原始长宽比，不得为了填满目标画布分别拉伸宽和高。
- 透明画布应紧凑且稳定，允许为对齐或描边保留少量透明边距。

### 3.2 炮塔

- 炮塔不设置绝对像素上限。长炮管可以让炮塔画布和完整俯视图超过 150 px。
- 炮塔必须与车身使用同一个来源比例。若车身相对几何权威图的缩放系数为 `s`，炮塔轮廓、炮塔转轴、炮口和所有保留特征也必须按 `s` 缩放。
- 炮塔画布尺寸按炮塔和炮管的实际需要决定，不得为了套入固定尺寸而单独缩小、压扁或截短炮管。
- 运行时的 `turretScale` 用于车型显示微调，不能替代源图片阶段的统一比例。

### 3.3 击毁图

- 击毁图必须从最终车身图片生成，不以重新生成的完整坦克轮廓作为几何基础。
- 击毁图与车身图使用完全相同的画布宽高、车身位置和车身缩放；不得平移、拉伸或重新适配车身。
- 损伤表现只在原车身轮廓内或其既有 Alpha 范围内修改。优先使用少量明显信号，例如烧蚀块、损坏的炮塔环、缺失或移位的炮塔；避免密集火焰、烟雾和细小碎片。
- `destroyedFitScale` 默认应保持 `1`。只有非坦克单位存在明确的展示需求时才允许配置例外，并应在 CSV 的 `notes` 中说明原因。

### 3.4 完整俯视图

- 分层坦克的完整图必须由最终车身和最终炮塔按正式转轴组合生成，不单独缩放两层。
- 完整图可以为了容纳炮管扩展画布，因此不受车身内容最长边 150 px 的限制。
- 完整图仅是组合结果或回退资源；实际战斗优先使用独立车身和炮塔。

## 4. 标准制作流程

### 4.1 检查与备份

开始修改前检查当前的 hull、turret、top、destroyed、对应 `.png.meta`，以及 `data/tank_visuals.csv` 中该车型的配置。

每辆待处理坦克使用一个 `data/tank_art/<kind>.json` manifest。首次制作时复制 `data/tank_art/tank.example.json`，填写选定源图、背景类型、统一缩放和源图关键点。字段约束见 `data/tank_art/tank-art-manifest.schema.json`。

manifest 中的输入必须是已选定的源文件，不能直接指向 `assets/resources/textures/units/` 下即将被覆盖的正式输出。三个输入角色分别是：

- `hull`：几何权威车身。
- `turret`：与车身处于同一来源比例的炮塔。
- `destroyed`：从该车身派生的击毁版本，源画布必须与 hull 完全一致。

`background` 使用 `alpha` 或 `chroma`；`chroma` 只清除接近纯 `#00ff00` 的背景。`sourceGeometry` 中的转轴、炮口和舱口坐标全部相对于各自未裁切源图填写。

正式执行前先运行只读演练：

```powershell
pnpm run tank:prepare -- --kind panzer4 --dry-run
```

演练会验证 manifest、输入、车身 150 px 上限、击毁源画布、关键点范围和最终输出尺寸，不修改任何文件。

确认输出计划后执行：

```powershell
pnpm run tank:prepare -- --kind panzer4
```

命令会在替换前自动备份四张正式 PNG、对应 `.meta`、`tank_visuals.csv`、生成的 `TankVisualDB.ts` 和本次 manifest。备份目录使用时间与修改原因命名，不覆盖已有备份。任一步骤失败时会从该备份恢复正式文件。

### 4.2 准备参考图

为每张输入图指定清晰角色：

- 几何参考：决定车体轮廓、部件位置和比例。
- 风格参考：决定色调、轮廓粗细和细节密度。
- 当前正式资源：决定必须保留的运行时转轴、炮口和画布关系。

参考图发生冲突时，先确定唯一的几何权威，再开始生成。

### 4.3 AI 重绘

只在原图不适合小尺寸显示或必须补齐独立图层时重绘。生成要求至少包括：

- 严格正俯视，无透视和侧面可见角度。
- 使用纯 `#00ff00` 背景，主体边缘与背景颜色明确分离。
- 保持权威图的外轮廓、长度/宽度比例、炮塔环中心、炮塔转轴和炮管长度。
- 车身、炮塔和击毁图各自输入角色明确；不要让模型自行重新设计缺失结构。
- 使用粗轮廓、主要装甲缝和少量可读舱盖，删除缩小后只会形成噪点的细节。

### 4.4 透明化与确定性后处理

1. 去除纯绿背景并生成带 Alpha 的中间图。
2. 按 `alpha >= 32` 计算内容包围盒并裁去无效留白。
3. 按同一来源缩放系数处理车身和炮塔；车身内容最长边不得超过 150 px。
4. 必要时匹配现有车身/炮塔的金属色调。
5. 描边只能向 Alpha 轮廓内部扩展，不能扩大或移动外轮廓。
6. Alpha 很低的残留像素应清零，最终图片不得残留绿色背景像素。

如果只是改色，必须保持 Alpha 和几何逐像素不变。几何调整应使用明确的区域操作，不重新生成整车。

`tank:prepare` 对 hull 和 turret 使用 manifest 中唯一的 `commonScale`。击毁图强制复用 hull 的裁切框、缩放和 padding，因此不能在准备阶段发生独立适配。

### 4.5 分层组合与击毁状态

1. 依据 `tank_visuals.csv` 的车体转轴和炮塔精灵转轴定位炮塔。
2. 由最终 hull 和 turret 生成 `{kind}_top.png`。
3. 以最终 hull 的画布和缩放为基础生成 `{kind}_top_destroyed.png`。
4. 对比存活车身和击毁图，确认画布、车身位置、外轮廓尺度完全一致。

以上步骤由 `tank:prepare` 完成。组合时会按两个转轴计算图层位置，并以车身中心为画布中心，在炮塔或炮管超出车身时对称扩展完整图画布。`topTrim` 始终描述独立 hull 的源像素画布，不使用完整组合图中的偏移。

### 4.6 Cocos 元数据与视觉配置

PNG 尺寸变化后，必须同步对应 `.png.meta` 中的：

- `width`、`height`
- `rawWidth`、`rawHeight`
- `trimX`、`trimY` 与裁切范围
- 顶点位置与 UV

然后更新 `data/tank_visuals.csv`：

- `topTrim*`：车身使用的源像素区域
- `turretTrim*`：炮塔使用的源像素区域
- `turretPivot*`：车身和炮塔图上的转轴
- `muzzleSprite*`：炮口位置
- `commanderHatchSprite*`：车长舱口位置
- 必要的显示缩放与偏移

源图片按系数 `s` 缩放时，上述源像素坐标必须同步乘以 `s` 并保持相对比例。

手工修改 CSV 时，配置更新后运行：

```powershell
pnpm run tank:build
```

它会从 `data/tank_visuals.csv` 重新生成 `assets/scripts/core/TankVisualDB.ts`。生成文件不得手工编辑。

正常使用 `tank:prepare` 时无需再手工执行该命令：准备流程会自动更新源像素几何、固定坦克的 `destroyedFitScale = 1`、生成数据库并审计当前车型。

## 5. 验收

先运行资源审计：

```powershell
pnpm run tank:audit
```

当前审计检查 PNG 和 `.meta` 是否存在、尺寸是否合法、是否残留纯绿、分层裁切和关键坐标是否越界。

完整验证使用：

```powershell
pnpm run tank:validate
```

该命令会重新生成视觉数据库、执行资源审计、运行坦克朝向与渲染测试，并进行 TypeScript 类型检查。

脚本通过后还必须进行视觉验收：

- 在实际地图尺寸下确认车型可辨，轮廓和主要结构没有糊成一片。
- 检查车体朝向、炮塔转轴、炮管方向、炮口特效和后坐位置。
- 检查炮塔旋转一周时没有偏心或绕错点。
- 检查完整图与运行时分层组合一致。
- 检查击毁图切换时车身不跳动、不缩放，画布和存活车身一致。
- 检查透明边缘、角落和缩小后的描边，没有绿边、白边或外扩轮廓。

## 6. 禁止使用的旧流程

以下做法已经废弃：

- 把多辆坦克统一到同一画布并强制放大到 400 px。
- 根据旧车型的硬编码椭圆或矩形，从完整俯视图自动切出车身和炮塔。
- 从完整坦克图批量叠加程序化烧痕生成击毁图。
- 只检查少数旧车型近白像素、并把结果追加到调试日志的旧审计方式。
- 修改 PNG 后只依赖 Cocos 手工重新导入，而不核对 `.meta` 和源像素几何。
