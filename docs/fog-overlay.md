# 自然迷雾边界

视野、敌人显示、攻击和单位遮挡仍使用原有六角格规则；地形迷雾使用一张连续遮罩。

- `UnitFogRenderer.ts` 直接借用 `FogOverlayRenderer` 的同一张 GPU 遮罩纹理。单位精灵、矢量回退、乘员、损伤图形、压制标记、阴影和遮挡轮廓通过共享的 `unit-fog-*.chunk` 计算像素透明度。噪声、`smoothstep` 和视野渐变端点与地形一致，但单位采用 `1 - 迷雾覆盖程度`，完全隐藏区的单位透明度为零。
- 移动和静止单位使用相同的空间渐隐。即使逻辑位置还在隐藏的起始格，驶入可见区域的车身也会连续显现；不等待抵达、不另加整单位淡入淡出，也不保存最后位置的深拷贝。`isUnitVisible` 仍独立用于名字、视野和攻击等规则。
- 单位 shader 使用迷雾四边形的逆世界变换，保持镜头平移、缩放、旋转后的采样对齐。地图内像素按连续场渐隐；已发现的边界单位允许伸出真实地图，未发现单位不会通过地图外的纹理留白泄露。动态合图不会改变世界空间的迷雾坐标。
- 建筑和树林遮挡继续保留，碉堡继续作为场景建筑处于迷雾下方。地面行驶履带痕继续按可见地形裁切，已知推动残骸沿用专用连续显示规则。
- 单位无需额外的迷雾纹理、移动模板遮罩或独立轮廓 pass。材质共享；视野动画、镜头变换或纹理对象变化时更新参数。静止帧不重复写入相同参数，退出场景只释放单位材质，共享纹理由地形迷雾管理。

- `FogMaskRaster.ts` 以每个六角格直径约 16 个采样点生成遮罩，每轴最多 512 像素。三轮可分离盒式模糊平滑六角格拐角，按地图覆盖权重归一化，避免地图外部和深阴影格造成额外暗边。
- R/G 通道保存当前视野渐变的两个端点，B 通道保留地图覆盖范围。进入下一圈、视野变化或临时战斗揭示变化时才重新生成和上传。
- `FogOverlayRenderer.ts` 缓存遮罩，镜头移动、缩放和动画进度不使缓存失效。动画帧只改 shader 的进度参数。
- 同尺寸视野更新只调用 `uploadData`，不对已绑定的纹理执行 `reset`。Cocos 3.8.8 按纹理对象身份缓存 GPU 绑定，重置会销毁底层资源却继续命中旧缓存；地图尺寸变化时创建新纹理和 SpriteFrame，再释放旧资源。
- `fog-overlay.effect` 对端点分别执行 `smoothstep(0.25, 0.75, ...)` 再插值，保留现有烟幕和舱盖逐圈渐变。轻微低频噪声固定在地图坐标中，没有时间动画。
- 单张四通道遮罩最多占用 1 MiB GPU 存储（无 mipmap），以一个 Sprite 绘制。首次效果加载期间或加载失败时使用原六角格覆盖层；退出场景释放纹理、材质和 SpriteFrame。
- 清理函数可重复调用，并兼容场景先销毁 Sprite 的顺序；不在清理时修改 Sprite 的材质属性，避免调用已清空的引擎材质状态。
- 渲染器独立保存迷雾节点引用，清理时不读取已销毁组件的 `Sprite.node`（Cocos 会将其清空）。组件或节点销毁后，迟到的重绘和 shader 加载回调也会忽略。

验证：`node tests/FogOverlay.test.js` 检查遮罩、动画端点、纹理缓存和资源释放；`node tools/validateFogGpu.cjs` 在独立无界面 Chrome 中编译生产片元 shader，验证 WebGL 1/2 的边缘透明度、插值、静态稳定性和地图外部裁切，输出 `tmp/fog-gpu/pixel-result.json` 与预览图。

GPU 检查使用 SwiftShader 验证正确性，不代表真实设备的帧率。最终效果和低端移动设备性能仍应在 Cocos 游戏预览中检查。

单位验证：`node --test tests/UnitFogRenderer.test.js` 检查共享纹理、材质缓存、镜头变换、地图边缘、异步加载和清理。`node tools/validateUnitFogGpu.cjs` 用生产精灵、矢量和轮廓 shader 在 WebGL 1/2 中检查 54 组像素结果，覆盖移动、视野端点插值、透明贴图孔洞、完整隐藏和地图外泄露；结果保存在 `tmp/unit-fog-gpu/pixel-result.json`。
