# 坦克俯视图制作与接入流程

这套流程把美术生成、几何配置、Cocos 元数据和战场注册作为一个交付单元，避免出现“调试界面正常、游戏里仍显示占位符”或“预览比例正确、运行时比例错误”。

## 1. 先锁定几何基准

- 三视图或已确认的现有素材是唯一几何权威。
- 记录车身长宽、炮塔长宽、炮塔座中心、主炮轴线、炮口、车长舱口。
- 明确车头朝向和车辆左右侧。俯视图旋转后，不能用屏幕上下直接代替车辆左右。
- 车身与炮塔必须使用同一来源比例；不要分别“铺满画布”。

## 2. 分层生成

### 默认美术风格：SU-152 已确认的清晰简化版

- 后续坦克及同类游戏单位图片默认采用“简化细节、加粗线条、保证主要细节到位”的风格；用户另有明确要求时按新要求制作。
- 依据三视图重新绘制，保持轮廓、比例和主要部件位置。原图裁切可作几何参考，不默认直接缩小抠图作为成品。
- 减少细小铆钉、划痕、密集纹理和细碎线稿；外轮廓及主要装甲分界采用粗而清楚的深色线。使用少量可区分的明暗色块，避免低对比细节缩小后糊成一片。
- 保留各车型的识别特征：炮管与炮盾、战斗室或炮塔形状、主要舱盖、发动机格栅、检修盖、履带及油箱等；位置、数量和比例以该车型参考为准，不能套用 SU-152 的具体布局。
- 在实际游戏显示尺寸下确认主要结构仍可辨认，再决定源图分辨率。必要时提高贴图像素密度，同时同步像素坐标、元数据及车长图尺度，保持游戏内占地和部件对齐。
- 风格参考：`source_art/tanks/su152/top-simplified-generated.png`；最终正常图：`assets/resources/textures/units/su152_top.png`。

### 资源拆分

- `*_top_hull.png`：只包含车身。
- `*_top_turret.png`：只包含炮塔、炮盾和火炮。
- `*_top.png`：用车身/炮塔支点确定性合成，不单独生成。
- `*_top_destroyed.png`：以车身为基准制作；若炮塔脱落，画布仍按车身比例，不保留透明炮管空间。
- 生成阶段使用纯 `#00ff00` 背景，抠图后缩到实际地图像素再验收。
- 无炮塔突击炮使用一体 `*_top.png`，不拆出可旋转炮塔。固定车体击毁图断炮后须保持车身原有显示比例和位置；不能独立紧裁后铺满原尺寸，使车身被放大或移位。

## 3. 小尺寸验收

- 必须以游戏实际尺寸或最近邻放大图检查，不能只看高分辨率生成稿。
- 检查主炮/副炮口径、长短和左右位置。
- 检查履带、油桶等车辆识别特征是否符合参考。
- 击毁图使用少量粗粒度损伤信号，避免微小碎屑、烟雾和画布外残骸。
- 击毁图保留正常图的主要涂装色相和未受损区域亮度，以局部焦黑、大破口、翻折装甲或断炮等清楚的大形状表现损伤；不能只整体染褐或压暗。具体破损组合按车型和用户要求选择，不要求所有单位都断炮。

## 4. 配置和元数据

1. 更新 `data/tank_visuals.csv`。
2. 同步每张 PNG 的 `.meta` 尺寸、UV 和顶点。
3. 执行：

   ```powershell
   pnpm run tank:build
   pnpm run tank:audit -- --kind maus
   ```

坐标全部使用源图像素：车身支点属于 hull 画布，炮塔支点、炮口和舱口属于 turret 画布。

## 5. 游戏接入

战场存活图和击毁图都直接使用 `TankVisualDB` 生成的 `TANK_VISUAL_KINDS` 注册表，不再维护第二份手写白名单。新增 CSV 行并重建数据库后，调试界面和战场会共享同一注册源。

## 6. 一键最终验收

```powershell
pnpm run tank:validate
```

该命令依次完成数据库重建、PNG/Meta/坐标审计、战场注册回归、朝向测试和 TypeScript 检查。全部通过后再进入 Cocos 实机目视验收。
