# 移动动画、静态场景与视野缓存

2026-10-26。本次优化适用于普通关卡和多区域关卡。

## 更新路径

- 连续移动帧复用已分配的车体、炮塔、步兵、舱盖、名称、状态文字和损伤履带节点，只更新位置；子节点继承父节点变换，避免重复位移。
- 转向和炮塔瞄准只重画该单位已保留的贴图槽位，并恢复共享池游标；推动残骸同步更新对应单位与可见性遮罩。
- 地形、建筑、树木、桥梁、地面装饰与静态阴影保留缓存。地形数据、美术资源、地图或尺寸变化时才重新构建；选择提示与边界等动态叠层单独绘制。
- 单位阴影、遮挡关系、尾气、火焰、履带痕迹等动态表现继续更新。
- 到达新格、改变朝向、击毁、增援等规则节点仍正常刷新状态。单位显示数量或可见性发生变化时重新绑定表现，避免旧图片残留。

## 视野失效条件

视野缓存只跟踪当前位置与相关友军的逻辑位置、朝向、炮塔状态、舱盖、乘员、无线电、视野范围、升级、烟雾、天气和地形视线阻挡。插值进度、弹药及无关的异地区状态不会引起重算。

多区域关卡用当前区的36格索引计算视野，避免每条视线反复扫描全图144～216格。临时揭示与击毁后的短暂保留视野加在缓存副本上，不会污染规则视野。跨区、读档、新地图均会自动失效。

## 验证

`tests/BattleAnimationPerformance.test.js` 的8项行为测试覆盖：60个移动帧无全场景重绘与视野重算、名称与子节点跟随、转向槽位复用、推动残骸、消失单位回退刷新、静态场景失效、视野失效条件与规则结果一致性。

相关回归共120项通过，包含多区域、单位图片池、音效、特效、迷雾、阴影、履带、残骸、桥梁与炮塔瞄准；项目及测试类型检查、Cocos web-desktop 最终构建通过。

固定种子四区地图的本机 Node CPU 基准：直接计算视野约1.415毫秒/次；状态相同的缓存读取约0.023毫秒/次。连续1100次读取只执行1次规则视野计算。这是视野函数的基准，不代表整帧帧率。

## 后续卡顿排查

移动缓存之外仍存在重复工作，本轮已处理：

- 敌方骰子排序的每个动画帧都会刷新行动字幕，字幕会调用 AI 目标选择、寻路与行动判断。排序帧现在只更新骰子外观，行动开始和规则变化时照常刷新字幕；结果停留期间不再重复绘制整盘骰子。
- 有行动单位但位置未改变时，动画缓存仍重做遮挡与单位阴影。现在静止帧跳过这两项工作。
- 树木、建筑逐个与单位匹配时，每次匹配都重新计算单位世界包围盒。现在同一次匹配只为每个对象计算一次。24个单位、300个遮挡物的行为测试中，包围盒计算从7500次降至324次。
- 步兵备用矢量轮廓此前会给远处的树木也创建遮罩；现在先做空间相交判断，并正确处理地图平移、旋转与缩放。
- 已绑定的轮廓材质反复上传相同迷雾参数。现在仅在迷雾、镜头或可见性策略变化时更新。
- 移动过程中，单位特效在更新前后各画一次。现在由 `lateUpdate()` 在当帧最终位置绘制一次，避免重复绘制且保持火焰、锁定圈和水波跟随单位。

这些计数由行为测试验证，不等同于设备上的实际帧率提升；加载阶段和整帧渲染仍需在最新构建上观察。

构建后的战场已实际执行前进与转向，未出现运行错误。原 `BattleSceneInfantryBloodDecals.test.js` 仍要求已经不存在的 `clampedX/clampedY` 源码表达式，使用修改前的 Git HEAD 同样失败；该旧断言单独记录，未为通过测试而改动镜头行为。

## 大型地图 AI 决策与字幕优化（2026-11-11）

- 主炮和机枪各自在一次目标选择中延迟计算视野，所有候选目标共用该集合。复用不跨调用，移动、天气、烟雾、无线电及乘员状态改变后自然重算；原有直接瞄准、射程和攻击合法性检查继续执行。硬核步兵和重炮保留各自判断路径。
- 骰子托盘创建完成后只计算一遍初始字幕。排序结束、当前骰高亮、消耗骰子、空转及精准射击消耗对子只刷新外观；已决骰使用执行结果并正常变灰。同步规则动作完成以及移动、攻击结算后的既有刷新点仍更新未决字幕。
- 没有新增跨帧视野缓存，也未改动地图视线几何或多分区后台调度。

固定种子 20261026，144 格连续大地图、42 个单位，本机 Node CPU 基准中，真实 `selectAIShootTarget()` 中位耗时从 152.805 ms 降到 9.923 ms；每次 `map.all()` 调用从 12224 次降到 764 次，枚举格数从 1760256 降到 110016。此项不包含 Cocos 渲染，不代表整帧帧率；测试场景由四区生成地图移除分区限制得到，并非用户截图存档。

- 修改前后目标选择对照 288 组全部通过：普通/多分区、敌我双方、三种模式、三种天气、烟雾与舱盖/无线电变化，比较主炮/机枪目标、命中格及随机平局处理后的 RNG 状态。对照针对相同输入的单次选择，不代表减少 UI 预演后整局 RNG 消耗与旧版完全相同。

## 视野局部查询与后台分帧（2026-11-11）

- `HexMap.tilesInRange()` / `tilesInBounds()` 直接查询坐标范围，避免每条视线创建全图数组；范围很大或地图稀疏时选择扫描现有格子。查询直接读取当前格子，地形修改、同坐标替换和新地图均无需维护额外缓存。
- 车长、步兵、车内和重炮只检测视程内且属于本区的目标格。几何遮挡候选限定在线段轴向包围盒并向外保守扩一格，仍执行原有六边形精确相交检测；中间格继续保留原有地形、高度、烟雾规则，斜线射界和双格观察原点不变。
- 多分区异地 AI 在单位开始、行动骰边界及步兵等级行动边界检查每帧 3 ms 软预算，并设置 32 次工作检查上限。超预算保留准确续点，由后续 `update()` 恢复，不使用重复定时器。一次完整攻击、移动结算或寻路不会被中途切断，因此单次原子操作仍可能超过预算。
- 本区单位与普通地图沿用原调度路径。跨帧期间阻止新操作；换任务、读档和销毁场景会清除续点，阶段、回合、行动队列、当前单位或胜负变化也会让旧续点失效。
- 同一次行动判断将支援路径首步传给转向目标和转向计划，执行转向也复用其支援首步。单次支援搜索中记住失败目标的搜索结果，避免同一不可达目标搜两遍；下一次行动仍重新检查地形和占位。

同一 144 格、42 单位 Node 基准中，真实 `selectAIShootTarget()` 中位耗时从上一轮 9.923 ms 进一步降到 1.760 ms；共享视野在 144 / 576 格下分别为 1.932 / 1.887 ms（此前为 6.750 / 26.393 ms），视野路径不再调用 `map.all()`。这说明增加远处地图格基本不再增加本地视野成本，不代表游戏整帧时间。

验证包括 1200 条随机几何视线与全图候选扫描对照、288 组不同单位/天气/舱盖/方向/区域的完整视野对照，以及远处新增 1000 格后的查询次数不变。分帧测试通过真实 `update()` 恢复 24 个坦克/步兵，确认行动顺序、骰子和最终 RNG 状态一致；覆盖即时攻击回调重入、过期续点、动画阻挡、重复续点、固定时钟工作上限及支援路径复用。

核心相关回归 141 项通过，随后新增的支援行动复用测试也通过；项目与测试类型检查通过。扩展扫描输出 379 项中 356 通过、23 失败：失败涉及旧测试依赖/源码断言、旧骰表及美术/关卡目录预期，全部在注入本轮修改前的 `BattleScene`、`FogOfWar`、`HexGrid`、`MultiRegion` 后复现。扩展扫描中的铁路障碍测试进程长时间未退出，已停止该测试子进程，不将该扫描视为全绿验证。记录位于 `tmp/large-map-ai/stage2-focused.log`、`stage2-regression.log` 和 `stage2-baseline.json`；新增测试为 `SpatialVisionPerformance.test.js` 和 `RegionalAIFrameBudget.test.js`。
