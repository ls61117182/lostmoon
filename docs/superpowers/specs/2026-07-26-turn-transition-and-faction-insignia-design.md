# 回合转场与阵营徽记设计

**日期：** 2026-07-26  
**状态：** 已获用户设计确认，待实施计划审阅

## 目标

在每次行动方切换时展示一段短暂的战场转场横幅，使玩家立即知道当前回合数和行动方；同时将五大阵营的徽记做成可在全局 UI 复用的资源。

## 范围

- 单人战斗：玩家行动切换至敌军行动，以及敌军行动和回合结算完成后切回玩家行动。
- PVP：由快照确定行动方时，使用对应阵营的横幅；等待对手状态不伪装成行动方转场。
- 全局阵营标识：战斗 HUD、PVP 信息、单位/阵营相关 UI 可复用同一徽记解析接口。

不修改战斗规则、AI 调度、回合结算逻辑或现有胜负界面。

## 视觉与文案

### 转场横幅

- 采用屏幕中央的横向情报带，而非全屏卡片。
- 横幅从左侧滑入，停留约 1.2 秒后淡出；显示期间屏蔽地图和阶段选择输入。
- 横幅左侧为阵营徽记；中部为主标题；副标题说明行动状态。
- 回合数必须包含在横幅内，例如：`第 04 回合 · 敌方回合`。不在横幅外增加独立回合数 UI。
- 敌方行动以警戒红的边线、角标和辅助文字提示；玩家/友军行动使用所属阵营徽记的强调色。
- 横幅淡出后才开放玩家阶段选择，或继续敌方 AI 调度，避免与骰子、着火检定、回合结算面板重叠。

### 阵营徽记

使用用户提供的源图，仅移除外部背景色并保留图形细节，不重绘、不替换为自制图形。最终透明 PNG 应保存为项目资源并通过统一映射读取。

| 阵营 | 徽记要求 |
| --- | --- |
| 美军 | 保留白色五角星及外层白色圆圈 |
| 英军 | 圆环由内向外依次为红、白、蓝、黄 |
| 苏军 | 保留红星与镰刀锤子 |
| 德军 | 保留历史式铁十字，中间黑色十字不透明；白色描边保持开放式轮廓，不闭合 |
| 日军 | 保留日之丸旗面 |

徽记是全局阵营资源，除转场外也用于后续阵营信息展示；所有位置通过一个阵营到资源的映射取得，避免分别硬编码图像路径。

## 技术设计

### 新增资源与映射

- 在 `assets/resources/textures/ui/factions/` 保存五张透明 PNG：`usa`、`britain`、`soviet`、`germany`、`japan`。
- 在核心层新增阵营 UI 元数据：资源路径、强调色、显示名称的本地化 key。
- 无法识别或未配置的阵营应返回安全的空徽记与中性颜色，且不阻断回合流程。

### 转场状态机

- `hidden`：没有转场，正常输入和现有阶段 UI 按当前逻辑工作。
- `entering`：横幅由左滑入，锁定新输入。
- `holding`：完整展示回合数、行动方、徽记和副标题。
- `leaving`：淡出并释放 UI；回调启动下一阶段。

转场必须是现有 `BattleScene.isBusy()` 的忙碌状态之一，并与骰子动画、回合结束事件、着火检定及 PVP 远端状态更新互斥。若任务已结束，不显示新的回合转场。

### 流程接入

1. 玩家回合结束：现有流程完成烟雾/着火等前置处理后，展示敌方阵营横幅；横幅结束才进入 AI 调度。
2. 敌方阶段与回合结算完成：递增回合数、完成胜负检查后，展示玩家阵营横幅；横幅结束才初始化玩家阶段选择。
3. PVP：快照显示本地可行动方或远端可行动方发生切换时，使用快照阵营展示横幅；进入“等待对手”时不重复播放。

## 可测试性与验收

- 单人模式首次进入与每轮切换，横幅文字均包含正确的回合数和行动方。
- 不存在横幅外的新增回合号。
- 五个阵营均能返回正确透明图标、强调色与名称；德军图标中心黑色十字保持不透明。
- 横幅显示期间，地图点击和阶段按钮不触发行动；淡出后正常恢复。
- 回合结算、胜负、骰子与 PVP 等已有流程不被重复触发或跳过。
- 英文和中文文案均有本地化值。

## 验证方式

- 为阵营 UI 元数据和横幅状态推进编写单元测试。
- 对五张导入后的 PNG 检查 alpha 通道、透明角点和关键像素（尤其德军中心黑十字）。
- 运行现有测试套件，并在单人和 PVP 流程中手动验证一次完整回合切换。
